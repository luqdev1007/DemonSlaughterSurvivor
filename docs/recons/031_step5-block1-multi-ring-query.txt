DetectContactDamageSystem (гр.8): кандидаты — враги. Смещение врага за тик
  складывается только в группе 5:
    ApplyMoveSpeedSystem  v = intent·MoveSpeed, |intent| ∈ {0, 1}
                          (ChaseTargetSystem нормирует, Blend сохраняет длину)
    ApplyPushSystem       v = Pushed.Velocity·(оставшихся/всего), |v| ≤ PushSpeed;
                          ApplyMoveSpeedSystem у отброшенных не работает (Exc<Pushed>)
    ResolveBodyOverlapSystem  v += dir·overlap/dt, overlap ≤ rP + rE
                          (при совпадении позиций overlap = rP + rE ровно);
                          отброшенных пропускает
    MoveSystem            pos += v·dt
  Отсюда смещение ≤ max(MoveSpeed·dt + rP + rE, PushSpeed·dt), и по всем врагам
    slack = max(maxEnemyMoveSpeed·dt + (rP + maxEnemyR), PushSpeed·dt)
  Числа: maxEnemyMoveSpeed 2.5 (Enemy_Devil.asset), rP 0.4 (CharacterConfig
  .asset), maxEnemyR 0.5 (Enemy_Troll.asset), PushSpeed 5 (Dash_Berserk
  .asset), dt = SimulationClock.Delta = 1/60 (RunEntryPoint.FixedDelta).
    slack = max(0.04167 + 0.9, 0.08333) = 0.9417
  Оценка сверху: скорость дьявола сложена с радиусом тролля. rings =
  ceil((0.9 + 0.9417)/1.0) = 2, то есть 5×5.
  dt берётся в Run, а не в Init: в Init часы ещё не шли, Delta = 0.

НАХОДКА: прежнее условие «0.9 + 0.042 ≤ 1.0» не учитывало коррекцию и
формально нарушалось. Замер на СТАРОМ коде, живой забег, сид 987654321,

  → потеря — враг, рождённый в этом же тике у края арены (спавн прижат к

случилось, игрок в рывке неуязвим (18 тиков против 7), то есть HP не
изменился бы. На новом коде тот же прогон — та же единственная потеря
новорождённого, снимки побайтово равны (§6.2).
