3. РЕШЕНИЯ, ПРИНЯТЫЕ БЕЗ КОСТИ (главный раздел для проверки)
----------------------------------------------------------------

Р1. ID записей — как в задании (snake_case: global_move_speed, dh_core, gem_ruby_wrath, relic_knight_banner,
    dh_weapon_blade). Остальной контент проекта — «тип.kebab» (perk.counter-strike). Вариант «переименовать под
    meta.global.move-speed» отверг: ID даны явно и навсегда; расхождение стиля — косметика. Контейнеры:
    meta.global_power, meta.run_rewards, tree.berserk/huntress/wizard; выданные перки — perk.meta.*.
Р2. Награды начисляются в момент конца забега, до показа экрана; «Забрать награды» — подтверждение (показывает
    копилку). Альтернатива «зачислять по кнопке» требовала бы хранить незабранное в сейве; так потерять награду
    невозможно ни уходом с экрана, ни закрытием игры. Выход через меню паузы тоже начисляет (как поражение, без экрана).
Р3. Магические осколки — по редкости ВЗЯТОГО предмета (одна карточка из окна), не по всем показанным. Вес для
    легендарного (100) добавлен мной — в задании были только 5/15/40.
Р4. Один экран итогов и для поражения: смерть теперь не уводит в меню через 4.5 с, а показывает итоги (timeScale 0).
    «Прокачка» с экрана итогов → меню с открытым хабом (IMenuRoute). «Сыграть ещё раз» → RunLauncher.RestartAsync
    (тот же уровень/герой, новый сид).
Р5. NotImplemented-узлы/свойства/самоцветы МОЖНО купить (метка «скоро», текст «ранг сохранится»). Иначе золотой узел
    недостижим (ворота 2 из 3 веток, а «Второй прилив» не реализуем). Цена: игрок может потратить валюту впустую —
    до релиза приемлемо. Альтернатива: запрет покупки + золотой узел только отладкой.
Р6. Один общий механизм параметров — Tuning: ключ = ID контента, поведение перка (→ ID перка через реестр) или тег
    («tag.Charge»), параметр — строка, формула пайплайна (Flat, Increased, More). Класс-узлы могут нести и статы, и
    тюнинг (например «Затяжная ярость» = duration Flat +1 у ability.ult.berserk) — тип узла влияет только на форму и
    правила древа. Новые параметры требуют одной строки чтения в системе-потребителе.
Р7. «Холодная ярость»: duration More −0.3 и mod_DamageTaken More −1 (бонус к получаемому урону → 0, модификатор не
    вешается). «Кровавая ярость»: duration More +0.5 и mod_HealingReceived Flat −1 — для этого в ульту добавлен слот
    HealingReceived More 0 (данные) и новый стат HealingReceived (он же нужен Парагону «Восполнение»).
Р8. «Чуткий палач» — порог Казни по низкому HP (LowHealthThreshold, сейчас 0.3) +0.05. В коде нет порога «запуска
    казни по HP элитки» — казнь бьёт любую элитку в секторе; ближайший по смыслу параметр — порог удвоенного урона.
Р9. Поведенческие свойства/реликвия — через существующий механизм перков-поведений: мета «выдаёт» PerkConfig с
    _grantedOnly (не попадает в пул уровней), SpawnPlayerSystem создаёт TakenPerk. «Жажда стали» — SteelThirstSystem
    по SwingEndedEvent.EnemyHits; «Гранат крови» — данные «Кровавой жатвы» (HarvestConfig, 3+ цели, 0.33% за цель):
    ровно 1% при 3 целях, больше при 4+ (отклонение от «лечит 1%»), и конфликт с перком «Кровавая жатва» (TryFind
    берёт одно поведение типа). Альтернатива — отдельная система лечения от мульти-удара (+1 система).
Р10. Реликвия «Знамя»: таран = обычный рывок героя, по заметённому отрезку которого (плюс 0.8 м) враги получают урон
    оружия × (300% + 40 п.п. × (ур.−1)) × теги (Сапфир натиска +15%) и бросок 16 м/с вдоль и в сторону; перезарядка
    12 − 1 × (ур.−1) с × множитель кулдаунов. Переиспользовал рывок героя и логику заметания (SweepDashPushSystem),
    НЕ механику тарана босса (у героя второй владелец движения недопустим, ARCHITECTURE §10). Отдельного замаха,
    визуала и индикатора готовности нет. Реликвия нейтральна: её перк без привязки к героям.
Р11. Топор: множители относительно меча героя (урон ×1.45 = 58/40, скорость атаки ×0.75 через More), а не абсолютные
    58 и 0.75 — абсолютных чисел в бою нет, урон меча 20 (Р-расхождение §1.5). Клинок = ×1.0/×1.0.
Р12. Уровень оружия: +3% Increased за уровень выше первого (ур. 5 = +12%); складывается с «Тяжёлой рукой» аддитивно:
    20 × (1 + 0.12 + 0.12) = 24.8, а не 20 × 1.12 × 1.12 = 25.1 (так устроен пайплайн, замерено §5).
Р13. Парагон «Мощь» — DamageDealt Increased +1% (общий множитель исходящего урона героя). «Опустошение» —
    NotImplemented: в DamageEvent нет признака «по области».
Р14. Регенерация — HealEvent каждый тик (regen × dt) через ApplyHealSystem (единая точка записи Health), не лайфстил.
Р15. Хаб и экран итогов строятся кодом в рантайме из MetaUiStyle (GUI_Parts как есть, без перекраски), а не префабами
    с готовой вёрсткой: так быстрее и данные (узлы, гнёзда, позиции) берутся из конфигов. Вкладка пересоздаётся при
    каждом изменении меты (меню — не горячий цикл). Билдеры — Editor/MetaUiBuilder (меню Game/Meta/…).
Р16. Шрифты: заголовки — существующий Cormorant SC Bold SDF; текст — Alegreya Sans (Google Fonts, OFL), статический
    TMP-атлас 182 глифа (латиница+кириллица+◆■□▲); JetBrains Mono не ставил (цифры читаются и так). Кириллица
    проверена на экране («Осколки воспоминаний», все вкладки) — пропусков глифов в логе нет.
Р17. Иконки — процедурные PNG (скрипт PIL по формам SVG прототипа), не game-icons.net: SVG в Unity требует пакета
    Vector Graphics (смена manifest.json — запрещено §9), а конвертера SVG на машине нет. Лицензии не нужны.
Р18. Сейв — один файл meta.json (а не 4 блока ARCHITECTURE §16 — стори-прогресса пока нет); §16 переписан.
Р19. Древа Охотницы и Колдуна: «Твёрдая рука» (+3% скорости атаки за ранг) и «Арканный фокус» (+4% урона) — только
    данные, код не менялся (модель масштабируется).
Р20. В хабе выбор оружия = экипировка: клик по невыкованному — ковка и сразу экипировка (как в прототипе).
