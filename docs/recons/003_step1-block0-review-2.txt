3. ПОЧЕМУ НЕ ВИДНО ASMDEF И USING — ДВЕ ПРИЧИНЫ
--------------------------------------------------------------------------------

ПРИЧИНА 1. Пустая сборка не попадает ни в один .csproj и ни в одно решение.

Unity генерирует .csproj только для сборок, в которых есть хотя бы один
скрипт. Все восемь сборок сейчас пустые, поэтому в решении
Deman-Slaughter-Survivor.slnx (перегенерировано в 15:00) нет ни одного
проекта игры — только пакеты: UniTask, VContainer, Leopotam.EcsLite,
R3.Unity, Unity.InputSystem и прочее.

Что при этом видит IDE: создаёшь первый скрипт в Assets/_Project/Core —
файл не принадлежит ни одному проекту решения, ссылок у него нет,
using Game.Core подчёркнут, автодополнение пустое. Выглядит как сломанные
asmdef. Asmdef при этом в полном порядке, и Unity компилирует без ошибок.

Проверяется в одну строку: в консоли Unity ошибок нет, а в IDE всё красное —
значит проблема в IDE, а не в сборках.

ПРИЧИНА 2. В корне лежит пустое решение от старого имени проекта.

    3DSample.sln   — 3 июня, ноль проектов внутри, только пустые GlobalSection

Это артефакт того времени, когда проект назывался 3DSample. Если Visual Studio
открывает его (а он открывается, если был открыт последним или выбран из списка
недавних), видно ровно ничего: ни сборок, ни пакетов, ни скриптов. Симптом
неотличим от «asmdef не работают».

Актуальное решение — Deman-Slaughter-Survivor.slnx. Формат .slnx новый,
его понимает Visual Studio 2022 начиная с 17.13; более старая версия его
просто не откроет, и есть соблазн открыть лежащий рядом .sln, то есть пустышку.
