1. Что делали
=====================================================================

Цель разработчика: в волне ×10 врагов от нынешнего (до 600 живых), чтобы было «месиво» как в VS,
но в 3D с расчленёнкой и VFX — и не получить 5 FPS. Целевая планка, выбранная разработчиком: 600.

Сделано:
  1. Стресс-уровень level.stress (коммит c984521).
  2. Временный зонд замеров (вне репозитория).
  3. Замеры: редактор и dev-билд, сценарии «стоит», «бежит по кругу», «идёт 2 с / стоит 1.5 с».
  4. Правка А — облегчённый риг дьявола в рантайме (коммит 73e5e7e).
  5. Правка Б — разделение толпы через снимок сетки, бит в бит (коммит 5d448a3).
  6. Правка В — разделение через тик (Р2) (коммит ee73d9a).
  7. Попутно (по просьбам разработчика, не производительность): подброс врагов рывком, плавная сила
     разделения (Т1, снизила дрожь толпы), шире коридор толчка рывка — коммит 15f9a51.

=====================================================================
3. Карта блока
=====================================================================

Стресс-уровень:
  DebugRunStarter._levelId (меню) → RunLauncher → LevelConfig level.stress → WaveTimelineConfig
  waves.stress → SpawnWaveSystem. В обычной игре не используется; запускается только зондом, который
  подменяет _levelId перед кликом.

Облегчённый риг:
  EnemyConfig._viewPrefab (Enemy_Devil.prefab с OptimizedRig) → ViewPool.Take → SourceFor(prefab):
  первый раз — Instantiate под неактивного родителя «View Templates» → проверка аниматора, аватара
  и имён открытых костей → AnimatorUtility.OptimizeTransformHierarchy → дальше все вьюхи
  клонируются из шаблона. Расчленённый префаб (Enemy_Devil_Cut) не трогается: CopyPose переносит
  только состояние аниматора, не кости. Шаблоны уничтожаются в ViewPool.Dispose.

Разделение толпы:
  RebuildSpatialGridSystem (конец гр. 13) → SpatialGrid.Add пишет (entity, x, z) → следующий тик,
  SeparateNeighborsSystem (гр. 4): сущность с (id & 1) == (tick & 1) зовёт QuerySnapshot (без
  обращения к пулу Position) → ResolvePush → Separation.Push; каждый тик всем — Blend(MoveIntent, Push).
  Обычный SpatialGrid.Query с живыми позициями для остальных потребителей не менялся.

Зонд (вне репозитория):
  [RuntimeInitializeOnLoadMethod] → находит DebugRunStarter, фиксирует сид 987654321 (подмена
  _random в SeedSource), ставит _levelId = level.stress, жмёт «Играть» → находит RunEntryPoint через
  RunLifetimeScope.Container → оборачивает каждую систему из EcsSystems._runSystems таймером →
  ProfilerRecorder по маркерам → держит героя неуязвимым, закрывает окно перков первой картой,
  ведёт героя (2 с по кругу R 10 м / 1.5 с стоит; подменяет MoveIntent после ReadMoveInputSystem) →
  пишет CSV по секундам и сводку по окнам 25–45 / 70–90 / 140–180 с, в конце Application.Quit.
  Дополнительно: размер пула и состав по префабам, смерти за секунду, максимум одного вызова
  удаления трупов и спавна, дрожь толпы (рывок позиции, поворот направления), плотность.
  ВАЖНО: пока зонд лежит в Assets/_Project/StressProbe, он перехватывает ЛЮБОЙ запуск play mode.

5. Развилки и решения
=====================================================================

  Целевая планка: 600 живых (разработчик).
  Сценарий-эталон: В1 «ходит по кругу» → на деле «2 с идёт / 1.5 с стоит» (агент, после двух
    неудачных вариантов: стоящий герой не достаёт лучников — их копится 400 из 600; бегущий на
    5 м/с не убивает никого, на 2 м/с не бьёт на ходу — меч срабатывает по сектору взгляда).
  Облегчение рига: А1 — в рантайме, шаблон в пуле (разработчик). Отвергнуто А2 — Optimize Game
    Objects в импорте FBX: сломал бы кости культей расчленённого префаба, если он из того же FBX.
  Прогрев пула: снят с плана — в реалистичном сценарии пул растёт на 2–19 вьюх за 40 с; рост
    раньше был артефактом копящихся лучников.
  Лимит расчленёнки на кадр (Б): не делали — меняет видимое; вернуться, если пики удаления трупов
    (до 20 мс при всплеске смертей) станут заметны.
  Разделение: снимок позиций — бит в бит (агент); Р2 пересчёт через тик (разработчик, принято
    руками); отвергнуто: лимит соседей на запрос, непроходимый контакт «враг ↔ враг».

7. Что осталось незакрытым
=====================================================================

  1. Рендер URP 4.5 мс: тени. Нужна развилка разработчика по картинке:
       — 4 каскада → 2;
       — враги без отбрасывания теней;
       — дистанция теней 50 м → меньше.
     Ожидание: заметная часть 4.5 мс и GPU.
  2. Синхронизация вьюх ≈1.8 мс: один менеджер вместо Update на каждой ViewInterpolator
     (условие §8 «LiveCap выше 150» уже сработало).
  3. Анимация 3.8 + скиннинг 3.0 мс — самая большая статья. Дешёвые шаги: облегчить риг лучника
     (172 узла, открыть кисть RightHand с арбалетом) — НО замер показал, что облегчение анимацию не
     снижает; реальные рычаги: обновлять анимацию дальних/внеэкранных врагов реже (culling,
     Animator LOD), меньше костей в риге (переимпорт с урезанным скелетом). Дорогой шаг —
     запечённая вершинная анимация на GPU; идти к нему, только если 1–2 не хватит.
  4. Рывок позиции бегущей толпы 10–20 мм/тик — источник не найден. Кандидаты: контактная
     коррекция у героя (ResolveBodyOverlapSystem), остановки лучников (HoldForRangedAttack), спавн
     и смерть (переиспользование id в треке зонда даёт ложные выбросы — проверить сначала это).
  5. Пики удаления трупов при всплеске смертей (до 20 мс за вызов): подмена на расчленённый
     префаб (353 узла, не облегчён) + BakeMesh + гибы. Вариант — облегчить и расчленённые префабы
     (нужно открыть кости культей) или лимит подмен на кадр (меняет видимое).
  6. Не замерено: обычный (не dev) билд — проверки LeoECS под DEBUG в dev-билде завышают цену
     симуляции; IL2CPP; герой в ульте; слабое железо.
  7. Плотность толпы при 150 врагах выросла после Т1 (пар ближе 0.5 м 28% → 37%) — следить на
     ручной игре.

8. Сценарий повторного замера
=====================================================================

  1. Скопировать 056_perf_materials/StressProbe и StressProbe.meta в Assets/_Project/.
  2. Дождаться компиляции; при необходимости поправить в зонде сценарий (WalkSeconds, StandSeconds,
     CircleRadius) и окна.
  3. Собрать dev-билд Windows (Mono) в папку вне проекта; запустить с
     -screen-fullscreen 0 -screen-width 1920 -screen-height 1080 -logFile player.log
     (или run_stress.sh <папка> после правки пути S).
  4. Зонд сам проиграет 180 с и закроет игру; результат — stress_probe_build_summary.txt и
     stress_probe_build.csv рядом с exe.
  5. Сравнивать с measurements/build_WalkStagger.txt (текущий эталон).
  6. После замеров УДАЛИТЬ Assets/_Project/StressProbe и StressProbe.meta — иначе play mode
     будет всегда запускать стресс-уровень. Откатить испачканный атлас TMP перед коммитом.
