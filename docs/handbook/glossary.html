Латиница

Определение сборки Assembly Definition, asmdef

Файл в папке проекта, объявляющий, что эта папка и всё под ней компилируется в отдельную .NET-сборку с заданным именем и заданным списком ссылок. Даёт три вещи: инкрементальную компиляцию, читаемый граф зависимостей и — главное — границу между слоями, которую держит компилятор, а не дисциплина.

Урок 01 · Что даёт asmdef
Сборка по умолчанию Assembly-CSharp

Сборка, в которую Unity складывает все скрипты, не накрытые ни одним asmdef. Внутри неё каждый класс видит каждый — то есть архитектурных границ не существует физически. В этом проекте не используется: у всех сборок autoReferenced: false, поэтому забытый вне asmdef скрипт падает с ошибкой вместо того, чтобы молча скомпилироваться.

Урок 01 · Что делает Unity без asmdef
Асинхронный метод async / await

Метод, помеченный async, компилятор превращает в машину состояний: тело переезжает в MoveNext(), а возвращаемый объект (UniTask, UniTaskVoid) создаёт билдер. Практическое следствие, которое ломает интуицию: исключение из такого метода не бросается в точке вызова — оно записывается в возвращённый таск, включая исключение, брошенное до первого await. Дойти до вызывающего оно может только через await.

Урок 06 · Машина состояний
Автоссылка из сборки по умолчанию autoReferenced

Поле asmdef. При true сборка автоматически видна из Assembly-CSharp. В проекте выставлено false у всех сборок — это страховка от скриптов, случайно оказавшихся вне asmdef.

Урок 01 · Форма файла
Токен отмены CancellationToken

Значение, которое асинхронная операция проверяет, чтобы понять, что ждать её результата больше некому. Отменённый токен приводит к OperationCanceledException на ближайшем await. Токен передаётся вниз по цепочке вызовов: каждый асинхронный метод принимает его параметром и отдаёт дальше. Ключевое, что легко забыть: токен прекращает ожидание, а не работу — см. отмена операции.

Урок 06 · Токен и жизнь объекта UI
Ошибки CS0246 и CS0234 CS0246 / CS0234: type or namespace not found

Ошибки компилятора «тип или пространство имён не найдено». В контексте asmdef — нормальный, ожидаемый результат попытки пересечь границу слоя, и основной инструмент проверки того, что границы расставлены верно. CS0246 выдаётся, когда корень имени неизвестен целиком (using VContainer из сборки без ссылки на VContainer). CS0234 — когда корень известен, а вложенная часть недоступна (using Game.View из Game.Simulation: namespace Game существует, Game.View из этой сборки не виден). Разница диагностическая, границу держат обе.

Урок 01 · Чек-лист приёмки
Запустил и забыл fire-and-forget

Запуск асинхронной операции без ожидания её результата. В UniTask это два разных приёма, а не один. Вызов без await и без Forget() — операция, за результатом которой не следит никто: исключение доживает до финализатора и печатается в момент сборки мусора, без стека вызывающего. Вызов с Forget() — операция, результат которой наблюдается ради ошибки. В UI законна только вторая форма, и только когда внутри метода стоит try/catch.

Урок 06 · Три способа не дождаться
Явный отказ от ожидания UniTask.Forget()

Метод-расширение UniTask. Не «намеренно не жду», а подписка на результат ради того, чтобы заметить ошибку: внутри он берёт awaiter, вызывает GetResult(), ловит исключение и отдаёт его обработчику необработанных исключений. Разница с выброшенным таском не в наличии сообщения, а в моменте: у Forget() — сразу и в кадре сбоя, у выброшенного — когда сработает финализатор.

Урок 06 · Три способа не дождаться
Токен жизни объекта Unity GetCancellationTokenOnDestroy / destroyCancellationToken

Токен отмены, срабатывающий при уничтожении объекта — в том числе при выгрузке сцены. На Unity 2022.2+ для MonoBehaviour это просто встроенное свойство destroyCancellationToken; для GameObject UniTask подвешивает собственный AsyncDestroyTrigger. Обязателен везде, где код после await трогает this, transform или ссылки на объекты сцены. Берётся до первого await: у уничтоженного объекта его уже не спросить — проверено, MissingReferenceException.

Урок 06 · Токен и жизнь объекта UI
Ограничение по платформам includePlatforms / excludePlatforms

Поля asmdef, ограничивающие список платформ, для которых собирается сборка. includePlatforms: ["Editor"] — обязательный признак сборки с редакторным кодом: UnityEditor доступен в Play Mode и недоступен в билде, поэтому редакторный код в runtime-сборке ломает только сборку проекта, а в редакторе выглядит здоровым.

Урок 01 · Editor-код в runtime-сборке
Сборка без движка noEngineReferences

Поле asmdef. При true сборка компилируется без ссылок на UnityEngine: недоступны Vector3, Mathf, Time и всё остальное. Строгий способ добиться того, чтобы симуляция физически не знала о движке; цена — собственный математический слой. В этом проекте выбран false, обоснование — журнал решений PROGRESS.md.

Урок 01 · noEngineReferences
Исключение отмены OperationCanceledException

Исключение, которым асинхронный код сообщает «меня отменили». По типу оно исключение, по смыслу — штатный ход, а не сбой, и обрабатывается отдельным catch, который идёт раньше остальных и ничего не логирует. Смешать его с ошибкой данных в общем catch (Exception) — значит красить успешные сценарии в красное и топить в них настоящие ошибки. UniTask по умолчанию не считает его необработанным исключением и не печатает (UniTaskScheduler.PropagateOperationCanceledException = false).

Урок 06 · Баг данных и отмена
Ручное управление ссылками на dll overrideReferences / precompiledReferences

Пара полей asmdef. По умолчанию сборка видит все скомпилированные dll, помеченные как auto-referenced (в этом проекте — DOTween.dll). overrideReferences: true отключает это поведение, и тогда доступны только dll, перечисленные в precompiledReferences. Способ запретить конкретную библиотеку в конкретном слое.

Урок 01 · Куда ложатся пакеты
Корневое пространство имён сборки rootNamespace

Поле asmdef. Unity подставляет его в шапку каждого нового скрипта, создаваемого в этой папке. Пустое поле означает файлы без namespace и массовое переименование позже — а переименование ломает ссылки на MonoBehaviour в префабах.

Урок 01 · rootNamespace пустой
Таск UniTask UniTask / UniTaskVoid

Замена Task для Unity: структура без аллокации кучи, продолжения выполняются в PlayerLoop главного потока, потоки не задействуются. UniTask — «этот результат кто-то обязан дождаться»; UniTaskVoid — «ждать нечего, ошибки обработаны внутри». Красная линия проекта (CLAUDE.md §7): внутри ECS-систем ни того, ни другого быть не должно.

Урок 06 · Три способа не дождаться
Ненаблюдённое исключение таска UnobservedTaskException

Исключение асинхронной операции, результат которой никто не запросил. В UniTask оно попадает в UniTaskScheduler.PublishUnobservedTaskException и по умолчанию печатается как Debug.LogException. Путей туда два, и они отличаются моментом: Forget() отдаёт исключение сразу, а полностью выброшенный таск — из финализатора ExceptionHolder, то есть в момент сборки мусора, спустя произвольное время и без вызывающего в стеке. Проверено на проекте: между броском и строкой в консоли прошло около четырёх секунд.

Урок 06 · Три способа не дождаться

Кириллица

Библиотека вне asmdef precompiled reference, overrideReferences

Готовая .dll, лежащая в проекте без собственного asmdef, — например пакеты NuGet в Assets/Packages. Такие библиотеки видны всем сборкам проекта автоматически, в обход списка ссылок asmdef. Проверено на проекте: using R3; компилировался внутри Game.Simulation, у которой ссылки на R3 нет. Закрывается двумя полями asmdef — overrideReferences: true и пустым precompiledReferences; после этого тот же using даёт CS0246.

Урок 04 · Граница сборки симуляции
Внедрение зависимостей Dependency Injection, DI

Способ получить зависимость, при котором объект не создаёт её сам и не ищет глобально, а получает снаружи — через конструктор либо, когда конструктор недоступен (MonoBehaviour, ECS-система), через поле или метод. Сам по себе приём ничего не решает, а переносит задачу сборки в одно место: этим местом становится корень композиции.

Урок 02 · Виды инъекции
Время жизни регистрации Lifetime: Singleton, Scoped, Transient

Свойство регистрации, отвечающее на два вопроса: сколько будет экземпляров и кто их уничтожит. Singleton — один на контейнер, где объявлен, уничтожает контейнер. Scoped — один на каждый скоуп, уничтожает свой скоуп. Transient — новый на каждый Resolve, и не уничтожает никто: контейнер такие объекты не отслеживает. Главное недоразумение — Singleton значит «один на контейнер», а не «один на приложение»: тот же тип, повторно объявленный в дочернем скоупе, даст второй экземпляр.

Урок 03 · Три времени жизни
Граница двух DI DI boundary

Разделение зон ответственности между VContainer (всё вне симуляции: сервисы, сцены, UI, сейвы) и LeoECS Lite DI (передача shared-данных в системы). Держится не договорённостью, а составом ссылок: Game.Simulation не ссылается на VContainer, поэтому система физически не может достать контейнер, и единственный оставшийся путь получить сервис — EcsSystems.Inject().

Урок 01 · Граница двух DI
Граф объектов object graph

Сеть созданных объектов и ссылок между ними, которую контейнер строит на фазе Resolve. Из графа выводятся порядок создания (сначала то, от чего зависят) и порядок разрушения (обратный). Ценность корня композиции в том, что граф в нём существует целиком и в одном месте; локатор служб размазывает его по всему коду, и ответ на вопрос «кто создал этот объект» перестаёт существовать.

Урок 02 · Что такое корень композиции
Дочерний скоуп child scope

Скоуп, построенный от контейнера другого скоупа. Регистрации родителя он не копирует: ищет у себя, не нашёл — спрашивает родителя, и так вверх до корня. Вниз поиск не идёт никогда, поэтому родитель физически не может зависеть от того, что объявлено в ребёнке. В этом проекте дочерний скоуп — это забег: создаётся на старте забега, разбирается на выходе, проектный уровень при этом не трогается.

Урок 03 · Иерархия скоупов
Инверсия зависимостей Dependency Inversion

Приём, разводящий направление зависимости и направление потока данных. Симуляция порождает данные для View, но зависеть от View не имеет права: интерфейс объявляется на нейтральном уровне (Game.Core), реализация живёт наверху, нижний слой работает с интерфейсом. Из того же принципа следует запрет синглтонов: синглтон — это способ достать верхний слой из нижнего, минуя инверсию.

Урок 01 · Направление зависимости
Инъекция в системы EcsSystems.Inject, LeoECS Lite DI

Один проход рефлексией по полям всех добавленных систем, заполняющий поля известных типов: EcsWorldInject, EcsPoolInject<T>, EcsFilterInject<…> берутся из мира, EcsCustomInject<T> — из аргументов вызова по совпадению типа. Не контейнер: ничего не создаёт, времён жизни не знает, графа не строит. Обязан вызываться строго между Add и Init — иначе не заполнится ничего, и молча.

Урок 04 · Инъекция в системы
Компонент ECS component

Единица данных на сущности: struct, только поля, имя — существительное без суффикса (Health, MoveSpeed). Ограничение where T : struct держит компилятор, а вот ссылочное поле внутри компонента — массив, список, ссылка на объект Unity — компилируется молча и ломает представление о компоненте как о данных. Пустой struct — тег (Player, Dead); компонент с суффиксом Event живёт один кадр и удаляется группой Cleanup.

Урок 04 · Формы компонента и системы
Корневой скоуп проекта RootLifetimeScope, VContainerSettings

Поле ассета VContainerSettings, куда кладётся префаб проектного скоупа. VContainer при загрузке первой сцены сам инстанцирует этот префаб и помещает в DontDestroyOnLoad — независимо от того, с какой сцены нажат Play. В проекте выбран как решение проблемы «запуск не с той сцены»: он не заводит второго пути инициализации, в отличие от редакторного хука и самодостаточного сценового скоупа.

Урок 03 · Запуск не с той сцены
Корень композиции Composition Root

Единственное место приложения, где известны все конкретные типы сразу и где собирается граф объектов. Стоит максимально близко к точке входа. Работает в три фазы: Register (объявить, что чем закрывается), Resolve (построить граф — ровно один раз) и Release (разобрать в обратном порядке). Логики в корне нет: он только соединяет. В этом проекте корней два уровня — проектный, живущий всё приложение, и корень забега, умирающий вместе с забегом.

Урок 02 · Что такое корень композиции
Локатор служб Service Locator

Глобальный реестр, у которого объект сам спрашивает нужную реализацию (Services.Get<T>()). Внешне похож на внедрение зависимостей, но прячет зависимость из сигнатуры, переносит ошибку конфигурации из компиляции в рантайм, делает порядок инициализации неявным и не даёт собрать объект в отрыве от окружения. GameObject.Find, FindObjectOfType и любой Resolve в игровом коде — это тот же локатор, где реестром служит сцена или сам контейнер.

Урок 02 · Локатор служб
Машина состояний асинхронного метода async state machine

Структура, которую компилятор строит из тела async-метода: поле «на каком я шаге», метод MoveNext() с ветками по шагам и билдер, отвечающий за возвращаемый объект. Всё тело обёрнуто в try/catch, и при исключении билдер зовёт SetException — кладёт ошибку в таск и возвращает управление нормально. Именно поэтому throw в первой строке метода не долетает до вызывающего: первой строки как отдельного кода не существует, она уже внутри машины.

Урок 06 · Машина состояний
Мир ECS EcsWorld

Хранилище сущностей, пулов компонентов и фильтров — все данные симуляции. В этом проекте не глобален и не вечен: живёт ровно один забег, регистрируется как Lifetime.Scoped в скоупе забега. Уничтожается методом Destroy(), а не Dispose(), — значит контейнер за него не отвечает и владельца надо назвать явно. Проверено: EcsSystems.Destroy() мир не трогает, и забытый world.Destroy() не даёт ни ошибки, ни предупреждения.

Урок 04 · EcsWorld и EcsSystems
Отмена операции cancellation

Сообщение асинхронной операции «результата больше никто не ждёт», передаваемое токеном отмены. Два свойства, которые надо держать в голове одновременно. Первое: отмена — не ошибка, у неё нет виноватого и её не чинят; в логе ей не место. Второе: отмена — не откат. Она прекращает ожидание, а не работу: проверено на проекте, что отменённая LoadSceneAsync даёт OperationCanceledException, а сцена всё равно догружается. Всё, что нужно разобрать после отмены, разбирается явным кодом.

Урок 06 · Баг данных и отмена
Оторванная ссылка на скрипт Missing (Mono Script)

Состояние компонента в сцене или префабе, когда Unity не может найти класс по сохранённой ссылке. Ссылка хранится как пара «GUID скрипта плюс имя сборки», поэтому переименование asmdef обрывает её по всему проекту — молча, при чистой консоли и компилирующемся коде. Отсюда правило: имя сборки фиксируется до того, как первый её скрипт повешен на префаб.

Урок 01 · Переименовал asmdef
Падение на первой ошибке fail fast

Правило: обнаружив недопустимое состояние, падать немедленно и громко, а не продолжать на значении по умолчанию. Смысл — сократить расстояние между причиной и симптомом: тихое продолжение переносит проявление ошибки на кадры и классы вперёд, где по симптому уже не найти источник. В проекте применяется дважды: реестр контента валидирует базу целиком при построении проектного скоупа, до первого кадра, и собирает все проблемы в одно исключение вместо падения на первой; регистрация компонента сцены форсирует резолв при построении контейнера. Обратная сторона правила — граница асинхронной операции, где падение легко теряется: там за громкость отвечает await с try/catch.

Уроки 05 · Падать рано, 06 · Три способа не дождаться
Перезагрузка домена Domain Reload

Пересоздание домена приложения при входе в Play Mode и при перекомпиляции, в ходе которого static-поля обнуляются. Начиная с Unity 2019 перезагрузку можно отключить ради быстрого входа в Play Mode — и тогда static-состояние переживает остановку игры. Симптом: первый запуск после компиляции исправен, второй ведёт себя иначе, а перезапуск редактора «чинит» проблему. Поэтому код не имеет права полагаться на то, что static обнулится.

Урок 02 · Синглтон и static
Предзагруженные ассеты Preloaded Assets

Список ассетов в Project Settings → Player, которые Unity загружает до первой сцены. В этом проекте туда кладётся VContainerSettings, и от этой ссылки зависит, поднимется ли проектный корень вообще. Защиты у поля нет: оно теряется при неаккуратном мердже ProjectSettings.asset, а симптом выглядит как «пропали все сервисы».

Урок 03 · Ассет настроек выпал из Preloaded Assets
Пул компонентов EcsPool<T>

Хранилище всех компонентов одного типа в мире, с доступом по сущности: Add, Get, Has, Del. Система не хранит компоненты у себя — она получает пул инъекцией (EcsPoolInject<T>) и работает через него. Именно поэтому система остаётся классом без состояния.

Урок 04 · Инъекция в системы
Реестр контента content registry

Таблица «стабильный ID → запись контента», собираемая один раз при построении проектного скоупа и валидирующая всю базу целиком (fail fast). Отдаёт данные и только по идентификатору — этим и отличается от локатора служб, который отдаёт поведение по типу. Промах по ID — ошибка кода, поэтому Get кидает ContentNotFoundException; отдельный TryGet существует ради единственного законного случая промаха — загрузки сейва, ссылающегося на вырезанный контент. Живёт в Game.Core, чистым C#, без единого типа Unity.

Урок 05 · Реестр против локатора
Синглтон Singleton

Частный случай локатора служб, где реестр состоит из одного элемента. Главная претензия не в глобальности, а в том, что объект сам управляет своим временем жизни: решает, когда родиться, и не решает, когда умереть. Это прямо противоречит требованию «один владелец у каждого объекта» (ARCHITECTURE.md §1). В Unity добавляются два своих механизма: выживание static-состояния при отключённой перезагрузке домена и непредсказуемый порядок уничтожения синглтонов на MonoBehaviour.

Урок 02 · Синглтон и static
Система ECS IEcsInitSystem, IEcsRunSystem, IEcsDestroySystem

Единица поведения: класс без состояния, реализующий нужные ему интерфейсы жизненного цикла. Порядок выполнения задаётся порядком вызовов Add — механизма групп или приоритетов в LeoECS Lite нет, поэтому тринадцать групп из ARCHITECTURE.md §10 держит один файл, читаемый сверху вниз. Run идёт в порядке добавления, Destroy — в обратном. Система, дописанная в конец вместо своей группы, не даёт исключения: механика просто срабатывает на кадр позже.

Урок 04 · Порядок систем
Скоуп времени жизни LifetimeScope

Форма, в которой корень композиции существует в VContainer: наследник MonoBehaviour, переопределяющий Configure(IContainerBuilder). Из того, что это компонент, следует всё остальное: граф строится в Awake (до Awake обычных компонентов, [DefaultExecutionOrder(-5000)]), разбирается в OnDestroy, а сам скоуп может пережить смену сцен через DontDestroyOnLoad. Не путать с контейнером: скоуп — объект сцены, контейнер — то, что он построил и держит в свойстве Container.

Урок 03 · Скоуп: контейнер плюс время жизни
Стабильный идентификатор контента stable content id

Строка, лежащая сериализованным полем внутри записи контента и не меняющаяся после первого релиза. «Стабильный» здесь не про уникальность и не про читаемость: идентификатор уезжает наружу игры — в сейв, в таблицу дропа, в мета-магазин, в конфиг DLC, — и обязан остаться понятным следующей версии билда. Поэтому им не может быть ни имя ассета, ни путь, ни индекс в списке, ни enum (сериализуется как int), ни прямая ссылка (в JSON-сейв её не записать). Всё остальное в ассете — имя, папка, порядок, иконка, баланс — меняется свободно. Поломка выглядит не как исключение, а как пропавший у игрока прогресс после патча.

Урок 05 · Идентификатор — контракт с прошлым
Точка входа Entry Point: IStartable, ITickable, IDisposable

Обычный C#-класс, которому контейнер раздаёт события жизненного цикла Unity, — замена MonoBehaviour там, где объект сцены не нужен. Initialize вызывается синхронно внутри Awake скоупа, Start — в следующем кадре и раньше MonoBehaviour.Start, PostStart — позже него, Tick — каждый кадр, Dispose — при уничтожении скоупа, в порядке, обратном созданию. Регистрируется одним вызовом RegisterEntryPoint<T>(), который объявляет тип под всеми реализованными интерфейсами сразу.

Урок 03 · Точки входа
Установщик Installer, IInstaller

Вынесенный кусок регистраций: класс с единственным методом Install(IContainerBuilder), который корень просто перечисляет. Лекарство от разрастания Configure, но не способ спрятать логику: установщик — всё ещё часть корня, и ветвлений по состоянию игры в нём быть не может ровно так же. Заводится, когда Configure перестаёт читаться с одного экрана, и не раньше.

Урок 03 · Установщик
Фильтр ECS EcsFilter

Набор сущностей, подходящих под маску «есть эти компоненты, нет вон тех» (Inc<…> и Exc<…>). Мир поддерживает фильтры в актуальном состоянии сам, при добавлении и удалении компонентов, поэтому обход фильтра в Run не стоит поиска и не аллоцирует. Приходит в систему инъекцией вместе с пулами включённых компонентов.

Урок 04 · Инъекция в системы
Циклическая зависимость сборок cyclic references

Ситуация, когда две сборки ссылаются друг на друга напрямую или через цепочку. Компилятор не собирает при этом весь проект, включая сборки, к циклу не относящиеся, а IDE продолжает показывать старое состояние и выглядит здоровой. Профилактика: создавать сборки строго сверху вниз по графу и связывать соседей по слою через интерфейс в Game.Core, а не напрямую.
