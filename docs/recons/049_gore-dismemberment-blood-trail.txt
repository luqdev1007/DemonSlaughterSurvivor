1. Расчленение
   - Живой демон — оригинальная модель (Enemy_Devil). В момент смерти
     ViewPool.Retire бросает кубик; при успехе берёт Enemy_Devil_Cut из
     того же пула вьюх, ставит в позицию/поворот трупа, копирует
     параметры аниматора (float/bool/int), состояние и время каждого слоя
     и локальную позу узла View (рут-моушен), возвращает оригинал в пул и
     отправляет порезанного в ту же механику смерти, что была: BeginRetire
     → триггер Death + отлёт трупа (FeedbackConfig: Knockback*).
   - Шанс: EnemyConfig._dismemberChance (0.35) и _dismemberedViewPrefab.
     Враг без порезанного префаба умирает как раньше. Сейчас префаб есть
     только у enemy.devil.
   - В режиме ульты: шанс × GoreConfig._berserkChanceMultiplier (2.0).
   - Только для смертей от взмаха (основной удар и контрудар). Огненный
     шлейф и прыжок не расчленяют — решение §5 Р3.
   - Выбор части (GoreDirector.PickPart): веса голова 0.4, рука со
     стороны удара 0.45, дальняя рука 0.15. Сторона — по знаку проекции
     направления «труп → источник удара» на right трупа; сторона руки —
     по положению её кости-обрубка. Удар почти в лоб (|проекция| ≤ 0.3)
     — обе руки с весом 0.3.
   - Отрыв: renderer части выключается, BakeMesh в текущей позе (кап уже
     в меше) → гиб из своего пула: MeshRenderer + Rigidbody (interpolate,
     continuous speculative) + BoxCollider по bounds меша × 0.8. Скорость:
     по направлению удара 4 м/с ± 30 %, вверх 3.5, плюс половина скорости
     отлёта трупа; случайное вращение до 540°/с. Через 3 с гиб становится
     кинематическим и за 1 с уходит в пол на 0.6 м, потом в пул. Лимит 24;
     при переполнении переиспользуется самый старый.
   - Пол для гибов: собственный BoxCollider 400×400 м под y = 0 на объекте
     «Gore», чтобы не зависеть от коллайдеров сцены (в Gameplay у Ground
     есть MeshCollider, у Tower — BoxCollider; с ними гибы тоже сталкиваются).

2. Кровь — см. §3, где что лежит. Попадание: брызги капель по направлению
   удара + направленный сплат на полу. Смерть: брызги крупнее + россыпь
   сплатов. Отрыв: фонтан из кости-обрубка 1 с (идёт за костью), капли за
   летящим гибом (до начала погружения), сплат там, где гиб впервые
   ударился об пол быстрее 1.5 м/с. Всё через пулы с лимитами; при
   исчерпании лимита эффект просто не играется (не отнимается у старого).

3. Трейл меча: лента между двумя точками на клинке (TrailBase — 30 %
   длины от рукояти, TrailTip — кончик), 64 сэмпла, затухание 0.15 с.
   Пишется, пока аниматор героя в одном из состояний атаки (список в
   конфиге) И кончик движется быстрее 3 м/с — второе условие отрезает
   замах и выход из удара. В берсерке — красный градиент.

4. Карта: путь данных
==========================================================================
Симуляция (только факты удара, гора там нет):
  AdvanceSwingSystem → DamageEvent.IsSlash = true
  ApplyDamageSystem → KillingBlow { SourcePosition, IsSlash,
      IsEmpowered = у источника есть BerserkMode }
  ReapDeadEnemiesSystem → IViewFactory.Retire(view, seconds,
      DeathBlow { Direction (как раньше для отлёта), IsSlash, IsEmpowered })
  PlayHitFeedbackSystem → IView.PlayHit(направление «источник → цель»)
Вьюха:
  ViewInterpolator.PlayHit → колбэк ViewPool.OnHit → GoreDirector.PlayHit
  ViewPool.Retire → SwapForDismembered (кубик в GoreDirector.RollDismember,
      Take порезанного, Activate, CopyPose, Return оригинала)
      → BeginRetire → GoreDirector.PlayDeath → GoreDirector.Dismember
      (PickPart → renderer off → SpawnGib → фонтан на обрубке, капли за
      гибом)
  GoreDirector.Tick (GoreRunner.Update): гибы (жизнь → погружение → пул),
      BloodFxPool.Tick ×7 (следование за костью/гибом, остановка, возврат)
  GibContact.OnCollisionEnter → GoreDirector.OnGibContact → сплат
  ViewPool.Return → DismemberableView.Restore (включить части обратно)
  Трейл: SwordTrail.LateUpdate; ViewInterpolator.SetBerserk/ResetFeedback
      → SwordTrail.SetBerserk/ResetTrail
DI: RunLifetimeScope — DebugGoreInput (IDebugGoreInput), GoreDirector,
    ViewPool(LevelConfig, IContentRegistry, GoreDirector).
Файлы: Core/DeathBlow.cs, Core/IDebugGoreInput.cs,
    Services/DebugGoreInput.cs, Configs/GoreConfig.cs,
    Configs/SwordTrailConfig.cs, View/GoreDirector.cs, View/GoreRunner.cs,
    View/BloodFxPool.cs, View/GibContact.cs, View/DismemberableView.cs,
    View/DismemberPart.cs, View/SwordTrail.cs,
    Art/Shaders/AdditiveTrail.shader.

5. Решения, принятые самостоятельно, и неочевидное
==========================================================================
Р1. Направление и сторона удара — из того, что уже было. Направление
    отлёта трупа (позиция трупа − SourcePosition) и есть направление
    удара; «горизонтальный слэш со стороны удара» реализован как
    сторона, с которой стоит источник относительно трупа. Настоящего
    направления проводки клинка (слева направо или наоборот) симуляция
    не знает; добавлять его не стал — это уже знание о взмахе, а не факт
    смерти. Если нужно «правый слэш рубит левую руку» — следующий шаг:
    вариант взмаха в DeathBlow.
Р2. Подмена — в ViewPool, а не в отдельном сервисе: пулом вьюх владеет
    ViewPool, порезанный префаб берётся из него же (Take/Return), и
    CompleteRetire возвращает его, как любую вьюху. Общий пул не менялся
    по устройству — добавились подмена и Restore частей при возврате.
    Гибы и кровь — в отдельном мини-пуле GoreDirector, как просили.
Р3. Расчленяют только смерти от взмаха (IsSlash). Огонь и прыжок —
    нет: «отрубить» огнём странно. Контрудар считается взмахом (идёт
    через тот же AdvanceSwingSystem).
Р4. Связь шанса с врагом — ViewPool при создании проходит по
    IContentRegistry.All<EnemyConfig>() и строит карту «префаб вьюхи →
    (порезанный префаб, шанс)». Симуляция про это не знает. Ошибки
    префаба (нет ViewInterpolator / DismemberableView / пустые части)
    — громкое исключение при старте забега.
Р5. GoreDirector — не ITickable VContainer: у Game.View нет ссылки на
    VContainer, тикает через скрытый MonoBehaviour GoreRunner на объекте
    «Gore». Объект создаётся в активной сцене забега и уничтожается в
    Dispose скоупа.
Р6. Кровь срабатывает и на смертельном ударе (PlayHit приходит до
    Retire), и на всех врагах, включая рыцарей и арбалетчиков —
    отдельного «кровоточит / не кровоточит» нет.
Р7. Чего не хватило в пакете Vefects. Пакет — это только напольные
    сплаты (билборды на полу, ~2 с жизни, разрастаются). Использованы как
    есть: попадание — VFX_Splat_Directional_01_Floor_Once, смерть —
    VFX_Splat_Directional_01_Floor_Bunch_Once, падение гиба —
    VFX_Splat_01_Floor_Rot_Once. Летящих брызг, фонтана и капель в пакете
    НЕТ — сделаны 4 простых ParticleSystem с каплями-сферами (меш сферы
    из пакета, unlit тёмно-красный). Это плейсхолдеры: нужны нормальные
    брызги (стрики/flipbook), если кровь должна читаться с игровой
    камеры. Сплаты Vefects живут ~2 с и исчезают — «лужи надолго» в
    пакете тоже нет.
Р8. Капли unlit: в Lit на тёмном полу арены они почти не видны.
Р9. Трейл: условие «активной фазы» — состояние аниматора из списка И
    скорость кончика ≥ 3 м/с. Окна урона из WeaponConfig не
    использовались, чтобы трейл не зависел от симуляции и работал для
    всех атак (слэши, спин, флип, прыжок) одинаково. Цена: на очень
    быстрых кадрах лента может начаться чуть до окна урона.
Р10. Отладочная клавиша G переключает «шанс 100 %» (в консоли пишется
    состояние). Состояние живёт в скоупе забега: в новом забеге снова
    выключено. Удаление: Services/DebugGoreInput.cs,
    Core/IDebugGoreInput.cs, регистрация в RunLifetimeScope, параметр
    конструктора GoreDirector и проверка в RollDismember.

6. Что проверено запуском
==========================================================================
- Play mode, живой забег, G включён: на смерти демона труп подменяется
  на Enemy_Devil_Cut, часть отрывается и летит (видно: отрубленная
  голова на земле рядом с безголовым трупом), гибы падают и тонут.
- Кровь в забеге: активны все 7 видов эффектов (счётчики объектов пула).
- Отдельно в тестовой сцене: сплаты Vefects лежат на полу правильно с
  нулевым поворотом, брызги и фонтан летят как задумано.
- Трейл: лента между основанием и кончиком в момент взмаха, затухает.
- Консоль чистая на всех прогонах.
НЕ проверено:
- Красный трейл в берсерке (до ульты в тестовых забегах не доходил).
- Множитель шанса в берсерке и распределение частей по сторонам —
  числами не мерилось.
- Цена кадра при массовых смертях (BakeMesh + Rigidbody) — не замерялась.
- Для теста герою временно поднималось здоровье в CharacterConfig.asset
  (стоящего героя убивают за ~20 с); изменение откачено, не закоммичено.

7. Сценарий ручной проверки
==========================================================================
1. Запустить забег, нажать G (в консоли: «forced to 100% is ON»).
2. Дать мечу убить несколько демонов. Ожидание: каждый убитый взмахом
   демон теряет голову или руку; часть отлетает в сторону удара,
   падает, оставляет сплат и через ~3 с уходит в пол. Из обрубка ~1 с
   бьёт фонтан, за летящей частью — капли.
3. Чаще должна отлетать рука со стороны героя или голова; дальняя рука
   — редко.
4. Попадания по любым врагам: брызги по направлению удара + пятно на
   полу; смерть — брызги крупнее.
5. Выключить G: расчленение примерно у трети убитых демонов; рыцари,
   тролли, арбалетчики — без расчленения, только кровь.
6. Трейл: белёсая лента на каждом взмахе, гаснет за доли секунды; в
   ульте (Q при полной ярости) — красная.
7. Смерть героя и рестарт забега: гибы, кровь и трейл не остаются
   висеть, ошибок нет.

8. Риски и долги
==========================================================================
- Копия позы — только текущее состояние слоя; если демон умер посреди
  перехода (бег → атака), порезанный стартует из одного состояния без
  бленда — возможен микрорывок позы в кадр подмены.
- Порезанный демон — ещё 352 узла в пуле на каждый одновременный труп
  (см. CLAUDE.md §8 про цену активации 350 узлов ≈ 0.86 мс): подмена
  платит Activate (Rebind) в кадр смерти.
- Гибы — первое использование физики Unity в проекте (только
  косметика, симуляция не трогается). Physics работает в стандартном
  FixedUpdate.
- Кровь на всех врагах одним цветом; рыцари в доспехах тоже красные.
- Брызги и фонтан — плейсхолдеры, см. Р7.
- Debug-клавиша G — удалить после приёмки (Р10).
- Предлагаю после приёмки записать в CLAUDE.md §8: «Гор — физика Unity
  для гибов» и «Трейл опирается на имена состояний аниматора героя в
  SwordTrailConfig — переименование состояния молча выключит трейл».
