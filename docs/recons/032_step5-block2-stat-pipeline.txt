  Решение разработчика — вариант 2: источник до группы 9 прибавляет тик
  (Invulnerability.TicksSpentBeforeDamage = 1). Прибавка к длительности
  НЕУЯЗВИМОСТИ, а не рывка: поле ассета по-прежнему значит «сколько тиков
  защищено».
  Проверено: 20 из 20; 0.5 с → ровно 30. Регрессионные тесты
  DashInvulnerabilityTests (5 случаев) без починки падают все пять.
  Эталон 987654321 совпал побайтово со снимками блока 1 — в том прогоне
  уязвимый тик ни разу не совпал с ударом, поэтому эталон доказывает
  отсутствие регрессии, а починку — тест.

5. СТОРОЖ СКОРОСТИ ВРАГА — ТОЧНЫЙ МЕХАНИЗМ
================================================================================
Что сравнивается: итоговый MoveSpeed.Value врага (сущность с тегом Enemy)
  СТРОГО БОЛЬШЕ максимума → InvalidOperationException. Равенство проходит
  (дьявол 2.5 = максимум 2.5).
Где хранится максимум сегодня: нигде постоянно. Его вычисляет
  WaveTimelineValidator.ResolveMaxMoveSpeed(LevelConfig.Waves) — максимум
  EnemyConfig.MoveSpeed по всем записям всех волн (весовым и
  гарантированным). Вызывают двое, каждый в своём Init, каждый хранит копию
  в поле: DetectContactDamageSystem._maxEnemyMoveSpeed (из неё запас
  запроса) и RecomputeStatsSystem._maxEnemyMoveSpeed (сторож). Функция
  чистая, вход один и тот же объект LevelConfig забега, конфиг в забеге не
  меняется — копии совпадают по построению. ResolveBodyOverlapSystem
  скорость не использует (только радиусы), её запас 0.
Когда проверяется: после Apply каждой грязной цели. Каждый рождённый враг
  помечен грязным, поэтому проверяется каждый враг хотя бы раз; дальше —
  при любом изменении его модификаторов. Непересчитанный враг имеет
  Value = Base ≤ максимума по построению.
Адрес в сообщении: id сущности, позиция (F2), итог, база, максимум, id
  таймлайна, список модификаторов MoveSpeed (SourceId, Op, Value), и что
  делать. Числа — инвариантная культура.
Проверено: тест EnemyFasterThanTheTimelineThrowsWithAnAddress (+10% →
  2.75 > 2.5, исключение с «Enemy entity 0», «2.75», «'test.haste'»);
  SlowingAnEnemyPassesTheGuard (−50% → 1.25, без исключения); живой забег —
  60 пересчётов врагов, ноль срабатываний.
Ограничение записано в CLAUDE.md §8: потолок — статичный кэш; первый
  законный ускоритель врагов — отдельная развилка.

7. РАЗВИЛКИ
================================================================================
Все основные (а–к) решены разработчиком, журнал PROGRESS 2026-09-26.
Однозначные решения агента:
  а) Ключ модификатора — (Target, Stat, SourceId), а не (Target, SourceId):
     иначе источник с двумя статами (элитка: HP и урон) затирал бы сам себя.
  б) Помечать грязным каждого рождённого, а не только имеющего
     модификаторы: так сторож проверяет каждого врага, и эталон проверяет
     пайплайн, а не его отсутствие. Цена — один пересчёт на рождение.
  в) Наследование от владельца — по статам, которые подчинённый несёт сам
     (а не по списку «статы оружия»): механизм тестируется уже сегодня,
     без стата оружия. Следствие записано в §5: призыв с MaxHealth и
     OwnerLink унаследует мета-бонус героя.
  г) StatModifiers — экземпляр на мир, создаётся в RunEntryPoint и
     инжектится, как SpatialGrid; EnemyFactory получает его в конструкторе.
  д) M на трупе игнорируется (Exc<Dead>): нажатие потребляется.
     Модификатор, повешенный при жизни, остаётся — труп всё равно не
     двигается.
  е) Буфер модификаторов в пересчёте: 64, рост удвоением — аллокация
     только при превышении, амортизированная.
