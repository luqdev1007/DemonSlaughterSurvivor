1. Тролль и реестр
- Enemy_Troll добавлен в ContentDatabase (после enemy.archer); реестр
  с ним собирается, ID уникальны.
- ViewPool откачен к версии до 050 (побайтово): враги для расчленения —
  только из IContentRegistry.

2. Почему валидация таймлайна (отчёт 022) пропустила тролля
- WaveTimelineValidator.Validate проверял только поля конфигов (ссылка
  не пустая, вьюха, HP, радиусы, веса). Таймлайн держит ПРЯМУЮ ссылку на
  ассет EnemyConfig, и ни одна проверка не искала врага по ID в реестре,
  поэтому «есть в базе или нет» было нечему заметить: незарегистрированный
  враг спавнился, а всё, что ищет врагов через реестр, молча его
  пропускало.
- Теперь Validate(timeline, registry): каждый враг (weighted и
  guaranteed) должен иметь ID, находиться в реестре и быть тем же ассетом.
  Вызов — SpawnWaveSystem.Init, то есть при старте забега; ошибка
  называет ID, имя ассета, таймлайн, волну и запись и говорит, что делать.
  Проверено падением: та же база без тролля →
  «EnemyConfig 'enemy.troll' (Enemy_Troll) is spawned by
  WaveTimelineConfig 'waves.gameplay', wave 1, guaranteed entry 0, but it
  is not registered in the ContentDatabase…».
- WaveTimelineRegistryTests: незарегистрированный враг падает (с ID и
  местом), самозванец с чужим ID падает, корректный проходит, и все
  уровни из настоящей ContentDatabase проходят против неё.

3. docs/ARCHITECTURE.md
- §3: абзац «Расчленение» — после переэкспорта любого *_Cut.fbx
  запускать Game/Build Cut Enemy Views; у рыцаря и стрелка без этого
  изменения не попадут в игру вовсе (клипы generic по пути
  mixamorig:Hips под View, сборщик распаковывает модель и переподвешивает
  Hips, связь префаба с FBX разорвана).
- §4: правило «враг таймлайна обязан быть в ContentDatabase тем же
  ассетом» и где оно проверяется.

4. Кровь на трейле меча
- PlayHitFeedbackSystem: на каждое применённое событие-взмах (IsSlash)
  зовёт у вьюхи источника IView.PlayWeaponHit() — ДО распаковки цели,
  потому что добитый этим ударом враг к группе 12 уже удалён.
- SwordTrail: каждый новый сэмпл получает «кровь» = 1 в момент
  попадания, линейно до 0 за BloodSeconds. Цвет сэмпла — смесь обычного
  (или берсерк) градиента и BloodColor. Краснеет лента, выпущенная после
  попадания; уже выпущенная часть остаётся белой — как кровь на клинке.
- Параметры: SwordTrailConfig.asset → _bloodColor (тёмно-красный →
  красный), _bloodSeconds 0.35.
- Проверено в забеге: кадр с первыми кровавыми вершинами — 6 красных,
  9 белых в ленте; снимок 051_registry-trail-blood/trail_blood.png.
  В ульте (красный трейл) кровь — тёмно-красная поверх красного, не
  смотрел.

5. Сценарий ручной проверки
- Забег: на каждом попадании меча хвост ленты красный ~0.35 с.
- Тролли расчленяются (G).
- Удалить Enemy_Troll из ContentDatabase → забег не стартует с
  понятной ошибкой; EditMode-тест WaveTimelineRegistryTests падает.
